01 · 总论：先校准问题

如果量子计算机还不能破密，我们为什么现在就要行动？

因为信息安全保护的是数据的有效保密期，不是今天的计算机能力。只要一份数据需要保密到未来，而攻击者今天能保存密文，那么风险已经发生；PQC 迁移的第一优先级，应是让被截获的会话无法在未来通过破解密钥交换被还原。

01

先保护“钥匙交接”

AES-256 这类对称加密仍被视为量子时代可用；脆弱点主要在用 DH/ECDH/RSA 建立会话密钥的阶段。先为 IPsec、MACsec、TLS、SSH 的密钥交换加入 ML-KEM。

02

再保护“谁有权开机”

设备还要证明硬件是真的、启动代码没被替换、密钥没被导出。Cisco Trustworthy 用硬件根信任、Secure Boot、SUDI 和运行时防御建立可验证链条。

03

把迁移做成运营能力

Secure Routers 8000 的价值不是单个算法，而是把安全处理器、硬件加速、IOS XE、统一策略和遥测放在一套可演进的平台上。

边界声明

“量子安全”不等于“绝对安全”。PQC 不会自动修复弱口令、终端失陷、错误授权、实现漏洞或供应链风险。本文将“PQC”“可信系统”“网络安全运营”分层讨论。

下一问

风险到底藏在加密链条的哪一环？如果只升级算法，会不会修错地方？

记忆锚点：Q-Day 是未来事件，HNDL 是今天的风险。

02 · 挑战：从数据寿命推导风险

PQC 时代真正的风险和挑战是什么？

第一性原理：机密性是一场“寿命不等式”

一份设计图、并购材料或关键基础设施遥测是否值得现在升级，不取决于谁能准确预测 Q-Day，而取决于三个时间量：数据还要保密多久（X）、组织完成迁移要多久（Y）、距离可破解现有公钥密码的量子能力还有多久（Z）。当 X + Y > Z，等待就等于接受未来泄密。

图 1｜HNDL 是“未来追溯解密”风险。来源：S1 pp.4, 8–9, 13；S3 pp.34–36。公式为本文决策模型。

精准定义

HNDL

Harvest Now, Decrypt Later：攻击者今天截获并保存密文，未来再推导私钥或会话密钥。

不是什么：它不要求攻击者今天破解 AES，也不要求 Q-Day 日期可预测。

精妙类比

不会过期的保险箱

攻击者今天打不开保险箱，却能把整只箱子搬走，等未来有“万能开锁机”再开。PQC 让今天的钥匙交接即使被录像，未来也无法复刻。

风险藏在哪一环？

环节典型机制量子风险架构动作
批量数据加密AES-256作为量子时代对称加密基线足够密钥长度与高质量随机数
会话密钥建立DH / ECDH / RSA数学基础受大型量子计算威胁引入 ML-KEM 混合交换
身份与签名RSA / ECDSA设备证书与软件签名也在风险面规划 ML-DSA、LMS
系统实现协议、密钥存储、启动链PQC 也可能实现错误硬件根信任、测试与算法敏捷性

证据：S1 pp.6–9, 12；S3 pp.35–39；NIST FIPS 203/204/205。

标准与时间线：哪些是事实，哪些不是企业通用死线？

NIST 于 2024-08-13 发布 FIPS 203（ML-KEM）、FIPS 204（ML-DSA）与 FIPS 205（SLH-DSA）。CNSA 2.0 面向美国国家安全系统；S1 p.7 概括为网络设备首选 2026、要求 2030。这不是所有企业在所有司法辖区的统一法定截止日。

资料勘误：S1 p.12 写作 RFC 9730；IETF 正式标准是 RFC 9370，并使用 RFC 9242 的 IKE_INTERMEDIATE 交换。

03 · 反思：密码升级不是换缩写

PQC 如何保护钥匙交接，又为什么采用混合模式？

PQC 是设计为抵抗经典与量子攻击的公钥算法族。它不是量子通信，也不需要量子计算机运行。ML-KEM 通过公开信道建立共享秘密，再由这个秘密派生 AES 会话密钥。

精准定义

ML-KEM

NIST FIPS 203 的模块格密钥封装机制。接收方生成公私钥；发送方用公钥封装出密文与共享秘密；接收方解封装得到相同秘密。

不是什么：它不直接替代 AES，也不是数字签名。

精妙类比

公开的“制锁模具”

Bob 把制锁模具（公钥）放在门外；Alice 用它做出一次性锁盒与双方可重建的钥匙。路人能拿到模具和锁盒，却还原不了钥匙。

图 2｜传统 + PQC 混合密钥交换。来源：S1 p.12；S3 pp.37–39；RFC 9370。

为什么先混合？

分散实现风险

协议集成仍年轻；两类数学假设降低新实现单点失败风险。

保持互操作

optional 让新端点用混合交换、旧端点暂用经典交换；它是过渡，不是终点。

可测量地收紧

先看协商成功率、MTU、CPU、密码引擎与隧道时间，再切换 required。

今天与明天的三条路径

路径本质优势限制
预置 PPK绕过量子脆弱的非对称交换快速保护高价值链路分发、熵与轮换复杂
QKD / KMS（如 SKS）外部或设备服务提供密钥按需获取密钥成本、标准与产品可用性需核验
协议内 ML-KEM在 IKEv2、TLS、SSH 中加 PQC沿用既有网络并获得密码敏捷性双方兼容；验证分片、性能和降级

来源：S1 pp.9–12；S3 pp.40–48；Cisco IOS XE PQC for IKEv2/SSH 指南。

下一问

即使隧道用了 ML-KEM，谁能证明路由器本人是真的、第一条指令没被换掉？

记忆锚点：PQC 保护钥匙的数学，Trustworthy 保护拿钥匙的设备。

04 · 启示：信任必须可验证

什么是 Cisco Trustworthy，为什么路由器必须先证明自己？

Cisco Trustworthy 不是一个单独功能或认证标签，而是一组贯穿设计、供应链、硬件身份、启动验证、密钥服务与运行时防御的政策、流程和技术。目标是让设备给出证据：硬件身份可信，代码真实且未修改，启动链逐级验证，运行期仍受保护。

精准定义

硬件根信任与信任链

硬件根信任是最先被信任、难以被软件重写的验证起点；信任链要求每一级代码执行前验证下一级。

不是什么：Secure Boot 不代表运行中的软件永远没有漏洞。

精妙类比

机场的接力安检

不是登机口只看一次证件，而是护照机构、值机、安检、登机口层层验证；上一关只把“已核验的人”交给下一关。任何一环不匹配，队伍就停下。

图 3｜经典 Trustworthy 信任链。来源：S2 pp.1–5；后量子启动链见 S3 p.30。

后量子启动链怎样升级？

S3 p.30 展示：硬件锚点加载微加载器；微加载器用 LMS 验证 Bootloader；Bootloader 用 ML-DSA-87 验证 OS；OS 再用 ML-DSA-87 验证应用镜像。ML-KEM 建立秘密，ML-DSA/LMS 证明代码，二者不是同一个工具。

下一问

当密钥交换与启动信任都要升级，路由器怎样同时承担更重的密码、安全和转发工作？

记忆锚点：信任不是“相信品牌”，而是让每一级都拿出可验证凭据。

05 · 工具：网络与安全进入同一数据路径

Cisco 8000 Series Secure Routers 如何应对 PQC 与融合安全？

架构答案是三层协同：Secure Networking Processor / Quantum Flow Processor 负责数据面与密码加速，IOS XE 提供可编程系统与单一镜像，Trust Anchor 与 PQC Secure Boot 保护平台自身。这不是在旧路由器旁边多放一个安全盒子，而是让路由、安全、密码与运维共享系统资源和可观测性。

图 4｜Secure Routers 8000 的处理分层。组件位置为认知简化，不代表芯片物理版图。

Secure Networking Processor 为什么是关键？

精准定义：SNP 把多核包处理、流量管理、集成接口、内联密码、安全加速、AI/ML 引擎和 Trust Anchor 汇聚在专用处理架构中。类比：像机场联合作业中心，安检、分拣、跑道调度共享一张航班计划，而不是反复搬运乘客。边界：集成不等于零开销，仍须测量数据面、密码引擎与服务面资源。

06 · 对比：创新要落到决策差异

与上一代相比，有哪些不得不提的创新？

最重要的不是型号数量，而是四个边界被重画：密码从附加功能变成全栈能力，安全从串联设备变成内联处理，资源从固定分割变成按意图调配，端口与吞吐从“开安全就缩水”转向硬件加速。

创新的代价是什么？

功能融合把容量工程从“每个盒子各算各的”变成“共享处理预算”。S3 pp.71–76 要求观察 RP CPU/内存、QFP DRAM、数据路径负载、密码引擎与 Secure Firewall 服务面。创新没有取消瓶颈，而是让瓶颈更可编程、更可观测。

07 · 落地：把密码迁移变成风险工程

如何规划一条可回退、可证明的 PQC 路线？

不要从“采购哪台路由器”开始；从“哪类数据最怕未来被解密、它经过哪些协议和设备、迁移窗口多长”开始。平台选型是风险排序后的结果。

1

发现

盘点数据寿命、算法、证书、隧道、固件签名、根信任与依赖方。

产物：CBOM
2

分级

用 X + Y > Z 排 HNDL 优先级，先保护长期机密。

产物：风险分层
3

试点

验证混合交换、MTU/分片、重协商、HA、性能与日志。

产物：互操作矩阵
4

迁移

先 optional 后 required；高风险网络优先并行 PQC Island。

产物：分波次计划
5

证明

监控算法、降级、QFP/密码引擎、证书与配置漂移。

产物：合规证据

热替换还是并行“PQC 岛”？

上线前十二项压力测试

  1. 资产：哪些链路承载需要保密五年、十年或更久的数据？
  2. 端点：平台、版本、许可与 FIPS 模式是否支持同一 ML-KEM 参数集？
  3. 身份：隧道认证、SUDI、PKI 与镜像签名是否分别规划？
  4. 协商：optional 会否静默降级？
  5. MTU：PQC 大报文是否触发分片、丢包或中间设备异常？
  6. 容量：并发建隧道、重密钥、故障切换时峰值如何？
  7. 复合负载：NAT、QoS、DPI、IPS、TLS 解密同时开启是否满足 SLO？
  8. HA：切换后 SA、路由与策略怎样恢复？
  9. 互操作：第三方 VPN、SSH、交换机与 PKI 是否端到端成功？
  10. 回退：条件、责任人、快照与恢复时间是否量化？
  11. 证据：能否证明目标算法在用，而非只证明隧道连通？
  12. 退役：经典算法退出日期由谁批准、谁追踪？

运行期看什么？

控制面

GL · Shared Vocabulary

完整术语表

AES-256

256 位密钥对称加密；像双方共有的一把高速保险柜钥匙。

CBOM

密码物料清单；记录算法、密钥、证书、协议与依赖的“配料表”。

CNSA 2.0

NSA 面向美国国家安全系统的算法套件，不是全球统一法规。

CRQC / Q-Day

足以破解主流公钥密码的量子计算机，以及其能力可用的时点。

DH / ECDH

经典密钥交换，其数学基础受大型量子计算威胁。

DMVPN

结合 mGRE、NHRP 与 IPsec/IKEv2 的动态多点 VPN。

FIA

QFP 数据路径功能调用序列，像数据包的工序单。

HNDL

先收密文、未来解密；风险在截获时已经形成。

IKEv2

为 IPsec 协商身份、算法与会话密钥的协议。

KEM / ML-KEM

密钥封装机制；ML-KEM 由 FIPS 203 标准化。

LMS

基于哈希的有状态数字签名，用于启动链早期验证。

MACsec

IEEE 802.1AE 二层链路加密。

ML-DSA

FIPS 204 模块格数字签名；证明来源和完整性，不建立会话秘密。

PQC

在经典计算机运行、设计为抵抗已知量子攻击的公钥密码。

PPK

后量子预共享密钥；快速但分发和轮换困难。

QFP

Cisco Quantum Flow Processor；这里的 Quantum 不等于量子计算。

QKD

量子密钥分发，与普通芯片运行的 PQC 不同。

信任链

从硬件根开始，一级验证下一级后才允许执行。

Secure Boot

启动时逐级验签，异常时停止加载。

SNP

融合包处理、内联密码、安全加速与流量管理的专用架构。

SUDI

制造时植入并链接根 CA 的 X.509v3 唯一设备身份。

TAm

Trust Anchor Module，提供 SUDI、安全存储、随机数与密钥服务。

TLS / SSH

应用传输与远程管理协议；其密钥交换需 PQC 化。

算法敏捷性

发现、替换、并行运行与退役密码算法的组织能力。
